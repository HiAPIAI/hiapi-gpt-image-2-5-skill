# Upgrade policy

The runtime checks the central directory first and repository policy second. Below `minimumVersion` blocks new paid creation; below `latestVersion` emits a notice and continues. If update sources are unavailable, the version is unverified but local validation still permits new creation; recovery and non-billing preflight remain usable. An update-service outage does not become a generation outage.

Version 0.3.2 is a soft upgrade: `latestVersion` is `0.3.2` and `minimumVersion` stays `0.3.1`. Version 0.3.1 still sends valid requests; its only defect is rejecting legal prompts above the previous limit locally, before the API sees them, so forcing every installed copy to update would cost more than it protects. Publishing 0.3.2 raises the notice and leaves 0.3.1 fully usable. Raising `minimumVersion` to 0.3.2 is a later decision once 0.3.2 has spread. The central `hiapi-skills` entry and this repository policy must agree; a successful central lookup takes precedence over the repository fallback. Preflight and recovery remain available to older copies.
